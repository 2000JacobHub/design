# Tailwindize Theme Literals

Convert every literal usage of a design token (in TSX/JSX, inline styles, SVG attributes, and arbitrary Tailwind classes) into the corresponding Tailwind utility class generated by an `@theme` token. Add tokens where a literal recurs; keep arbitrary values only when no semantic token fits.

## When to Apply

Use this skill whenever you see in a Tailwind v4 codebase any of:

- `style={{ background: "#f5d28a" }}` / `style={{ color: "var(--color-stardust-gold)" }}`
- `bg-[#f5d28a]` / `text-[#hex]` / `border-[#hex]`
- `bg-[linear-gradient(180deg,#hexA,#hexB)]`
- `shadow-[0_0_12px_rgb(...)]`, `rounded-[10px]`, `text-[11px]`, `tracking-[0.16em]` when the value recurs ≥ 2 times
- SVG `fill="#hex"`, `stroke="#hex"`, `<stop stopColor="#hex" />`

## Output Mapping Cheatsheet

| Literal form                                            | Replacement                                            | Where it lives        |
|---------------------------------------------------------|--------------------------------------------------------|-----------------------|
| `bg-[#f5d28a]` / `text-[#f5d28a]` / `border-[#f5d28a]`  | `bg-stardust-gold` / `text-stardust-gold` / `border-…` | `className`           |
| `bg-[#hex]/40`                                          | `bg-stardust-gold/40`                                  | `className`           |
| `bg-[linear-gradient(180deg,#a,#b)]`                    | `bg-linear-to-b from-a to-b`                           | `className`           |
| `bg-[linear-gradient(135deg,#a,#b)]`                    | `bg-linear-135 from-a to-b`                            | `className` (v4 only) |
| `shadow-[0_0_12px_rgb(245_210_138/0.65)]`               | `shadow-gold-pulse` (add token if missing)             | `className`           |
| `rounded-[10px]`                                        | `rounded-input` (project token) or `rounded-lg` (default 8px / `xl` 12px) | `className` |
| `text-[11px]`                                           | `text-xs` (when `--text-xs: 11px` is registered)       | `className`           |
| `style={{ color: "var(--color-x)" }}`                   | drop `style`, add `text-x` class                       | `className`           |
| `style={{ fontFamily: "var(--font-sans)" }}`            | drop `style`, add `font-sans` class                    | `className`           |
| SVG `fill="#F5D28A"` / `stopColor="#F5D28A"`            | `fill="var(--color-stardust-gold)"`                    | SVG attribute         |
| SVG `stroke="#F5D28A"`                                  | `stroke="var(--color-stardust-gold)"`                  | SVG attribute         |

> SVG attributes (`fill`, `stroke`, `stopColor`, `stop-opacity`) and dynamic `style={{ background: … }}` cannot consume Tailwind utility classes, so they must use `var(--color-…)` to reference an `@theme` token. **That is the canonical form for SVG.**

## Token Namespaces Tailwind v4 Auto-Exposes

Defining a CSS custom property inside `@theme { … }` automatically produces utility classes:

| `@theme` namespace        | Generated utility prefix       | Example                                    |
|---------------------------|--------------------------------|--------------------------------------------|
| `--color-*`               | `bg-*` / `text-*` / `border-*` / `fill-*` / `stroke-*` / `from-*` / `to-*` / `via-*` | `--color-stardust-gold` → `bg-stardust-gold` |
| `--font-*`                | `font-*`                       | `--font-display` → `font-display`          |
| `--text-*` (+ `--…--line-height`) | `text-*` (line-height paired) | `--text-xs: 11px` → `text-xs`        |
| `--radius-*`              | `rounded-*`                    | `--radius-input: 10px` → `rounded-input`   |
| `--shadow-*`              | `shadow-*`                     | `--shadow-gold-pin` → `shadow-gold-pin`    |
| `--tracking-*`            | `tracking-*`                   | `--tracking-eyebrow` → `tracking-eyebrow`  |
| `--leading-*`             | `leading-*`                    |                                            |
| `--blur-*`, `--spacing-*` | etc.                           |                                            |

> Use bare `@theme { … }` (NOT `@theme static { … }`). `@theme static` only emits the CSS variables but **does not extend/override Tailwind's built-in namespaces** (`--text-*`, `--font-sans`, `--radius-md`, …). Custom values silently fall back to defaults under `static`. Always use `@theme`.

## Workflow

Copy this checklist into your scratchpad and track progress:

```
- [ ] 1. Inventory literals across the target files
- [ ] 2. Bucket recurring literals → propose new tokens
- [ ] 3. Extend @theme in globals.css with new tokens
- [ ] 4. Replace literals component-by-component
- [ ] 5. Verify with linter and a render check
```

### 1. Inventory Literals

Run a series of greps. Drive them with `rg` / Cursor `Grep` rather than reading every file by hand:

```bash
# hex literals (case-insensitive)
rg -i --type tsx '#[0-9a-f]{6}\b'

# var() consumption in TSX (these should become utility classes)
rg --type tsx 'var\(--(color|font|text|radius|shadow|tracking|leading)-[a-z0-9-]+\)'

# arbitrary tailwind colors
rg --type tsx '(bg|text|border|fill|stroke|from|to|via)-\[#'

# arbitrary tailwind sizes / radii / shadows
rg --type tsx '(text|leading|tracking|font|rounded|shadow|w|h|p|m|inset|top|left|right|bottom|gap)-\[[^\]]+\]'

# linear/radial gradients with hex
rg --type tsx 'bg-\[linear-gradient'

# SVG hex attrs (fill / stroke / stopColor)
rg --type tsx '(fill|stroke|stopColor)=\"#'
```

### 2. Bucket → Propose Tokens

For every literal that appears ≥ 2 times, prefer adding a token over inlining. Group by namespace:

- Colors → semantic name (`stardust-gold`, not `gold-300`).
- Shadows → ordered by blur radius and purpose: `dot < pin < pulse < soft < cta < cta-hover`, plus `ring` / `recess` for inset variants.
- Radius → semantic role: `input` / `card` / `panel` / `pill`; reuse Tailwind defaults for `sm` (4px) / `md` (6px) / `lg` (8px) / `xl` (12px).
- Type scale → numeric ladder (`2xs`, `xs`, …, `6xl`) with paired `--text-…--line-height`.

When a literal recurs only once, leaving it as an arbitrary `[value]` is acceptable.

### 3. Extend `@theme` in `globals.css`

Add tokens inside the existing `@theme { … }` block. Example pattern (use the project's actual color values):

```css
@theme {
  /* Colors → bg-* / text-* / border-* / fill-* / stroke-* / from-* / to-* / via-* */
  --color-cosmic-black: #050507;
  --color-stardust-gold: #f5d28a;
  /* … */

  /* Font family → font-sans / font-display */
  --font-sans: "Space Grotesk", system-ui, sans-serif;
  --font-display: "Space Grotesk", system-ui, sans-serif;

  /* Type scale → text-2xs / text-xs / … / text-6xl (line-height paired) */
  --text-xs: 11px;
  --text-xs--line-height: 16px;
  /* … */

  /* Radius → rounded-input / rounded-pill / rounded-card / rounded-panel */
  --radius-input: 10px;
  --radius-pill: 999px;
  --radius-card: 14px;
  --radius-panel: 20px;

  /* Shadow → shadow-gold-dot / shadow-gold-pulse / shadow-gold-cta / ... */
  --shadow-gold-dot: 0 0 8px rgb(245 210 138 / 0.6);
  --shadow-gold-pin: 0 0 10px rgb(245 210 138 / 0.55);
  --shadow-gold-pulse: 0 0 12px rgb(245 210 138 / 0.65);
  --shadow-gold-soft: 0 0 18px rgb(245 210 138 / 0.5);
  --shadow-gold-cta: 0 0 22px rgb(245 210 138 / 0.42);
  --shadow-gold-cta-hover: 0 0 28px rgb(245 210 138 / 0.6);
  --shadow-gold-ring: inset 0 0 0 1px rgb(245 210 138 / 0.36);
  --shadow-gold-recess: inset 0 0 12px rgb(245 210 138 / 0.08);
}
```

### 4. Replace Literals

For each file from step 1, apply mappings from the cheatsheet. Patterns:

**TSX inline style → className**

```tsx
// Before
<div className="h-20" style={{ background: "#f5d28a" }} />

// After
<div className="h-20 bg-stardust-gold" />
```

**Dynamic color via @theme variable** (when data is dynamic)

```tsx
// Before
<div style={{ background: color.hex }} />

// After
<div style={{ background: `var(--color-${color.name})` }} />
```

**Hex gradient → Tailwind v4 gradient utilities**

```tsx
// Before
<i className="bg-[linear-gradient(90deg,#f5d28a,#7fb9be)]" />

// After
<i className="bg-linear-to-r from-stardust-gold to-accent-teal" />
```

Tailwind v4 ships `bg-linear-to-{r,l,t,b,tr,tl,br,bl}` and `bg-linear-{angle}` (e.g. `bg-linear-135`). Prefer named directions; use angle form only when direction is non-cardinal.

**Arbitrary shadow → token**

```tsx
// Before
<i className="bg-stardust-gold shadow-[0_0_12px_rgb(245_210_138/0.65)]" />

// After
<i className="bg-stardust-gold shadow-gold-pulse" />
```

**SVG hex → CSS var (cannot use Tailwind class here)**

```tsx
// Before
<stop offset="0%" stopColor="#F5D28A" stopOpacity="0.32" />
<circle fill="#7FB9BE" />

// After
<stop offset="0%" stopColor="var(--color-stardust-gold)" stopOpacity="0.32" />
<circle fill="var(--color-accent-teal)" />
```

**Arbitrary text size → semantic token**

```tsx
// Before:    <span className="text-[11px]">…</span>
// After:     <span className="text-xs">…</span>           // requires --text-xs: 11px in @theme
```

### 5. Verify

After all edits in a file:

1. Run the linter on every changed file (`ReadLints` in Cursor). Tailwind's eslint plugin will surface modernization opportunities like `tracking-[0.1em] → tracking-widest`, `z-[2] → z-2`, `-top-[260px] → top-[-260px]`. Apply them as bonus cleanup.
2. Re-grep with the inventory commands; the only remaining hits should be **intentional showcase data** (e.g. a color-token gallery rendering its own hex string).
3. Render the page in the browser to visually confirm zero regressions.

## Two Critical Pitfalls

### Pitfall 1: `@theme static` silently ignores overrides

`@theme static { … }` only emits CSS variables. It does NOT extend or override Tailwind's built-in `--text-*`, `--font-*`, `--radius-md`, `--leading-*` namespaces. Any custom `--text-xs: 11px` under `static` is silently dropped and the default `0.75rem` is used instead. **Always use the bare `@theme { … }` form.**

### Pitfall 2: Unlayered base resets beat utilities

A global reset like `button, a { color: inherit; font: inherit; }` written outside `@layer base { … }` lives in the unlayered cascade level, which Tailwind v4 places **above** the `utilities` layer. That makes `text-[11px]` and `text-xs` on buttons/links silently no-op. Wrap such resets in `@layer base { … }`:

```css
@layer base {
  button, a { color: inherit; font: inherit; }
  button { cursor: pointer; }
}
```

## Anti-Patterns

- **Don't** invent a new token for a one-off value — leave the arbitrary `[value]` in place.
- **Don't** override Tailwind defaults you actively use (e.g. don't redefine `--radius-md` if you also write plain `rounded-md` elsewhere expecting 6px). Pick a fresh name (`rounded-input`) instead.
- **Don't** replace literals inside showcase / documentation components that intentionally render the literal value as visible content (color gallery, code block, design-token table).
- **Don't** mix `bg-linear-…` (v4) with the legacy `bg-gradient-to-…`. Standardize on `bg-linear-…` and `bg-radial-…` in v4 codebases.

## Final Checklist

- [ ] No `bg-[#…]` / `text-[#…]` / `border-[#…]` left for colors that have a `@theme` token
- [ ] No `bg-[linear-gradient(…,#…)]` left — converted to `bg-linear-* from-* to-*`
- [ ] No `shadow-[…]` left for repeated shadow shapes — moved to `--shadow-*` tokens
- [ ] No `rounded-[Npx]` left where a `--radius-*` or Tailwind default matches
- [ ] No `text-[Npx]` left where `--text-*` covers it
- [ ] All SVG `fill` / `stroke` / `stopColor` hex strings use `var(--color-*)`
- [ ] `globals.css` still uses `@theme` (not `@theme static`)
- [ ] Global resets wrapped in `@layer base { … }`
- [ ] `ReadLints` reports zero errors on the touched files
